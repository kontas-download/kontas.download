# Развёртывание на сервере

Минимальный сервер: 1 vCPU, 1 ГБ RAM (лучше 2 ГБ), 20 ГБ диска, Linux с Docker 24+ и Compose v2. Приложение работает в одном экземпляре (база SQLite лежит в файле), поэтому балансировщики и бессерверные платформы без постоянного диска не подходят.

Схема: контейнер приложения `kontas-app` доступен только через контейнер Caddy `kontas-caddy`, который сам получает и продлевает сертификат HTTPS. Наружу открыты только порты 80 и 443.

## Подготовка

1. Направьте DNS-запись домена (например, `accounting.example.com`) на IP сервера. Откройте порты 80 и 443.
2. Установите Docker и скопируйте репозиторий на сервер (`git clone`; для клиентов используйте `git archive HEAD`, чтобы не передавать историю).
3. Если на сервере мало памяти (1 ГБ), добавьте swap 2 ГБ на время сборки образа: `fallocate -l 2G /swapfile && chmod 600 /swapfile && mkswap /swapfile && swapon /swapfile`. После сборки он не нужен.

## Первый запуск

```bash
cd deploy
cp .env.example .env
# заполните DOMAIN, SMTP_ENCRYPTION_KEY (команда для генерации в файле), ADMIN_EMAIL
mkdir -p data && chown -R 1000:1000 data
docker compose -f docker-compose.server.yml --env-file .env up -d --build
docker logs kontas-app      # здесь один раз показан пароль администратора, если ADMIN_PASSWORD пуст
```

Переменные файла `.env`:

- `DOMAIN` — публичное доменное имя (обязательно).
- `SMTP_ENCRYPTION_KEY` — 64 шестнадцатеричных символа (обязательно); им шифруются пароли SMTP, хранящиеся в базе.
- `ADMIN_EMAIL`, `ADMIN_PASSWORD` — используются только при первом запуске, когда базы ещё нет. Если `ADMIN_EMAIL` пуст, будет `admin@kontas.local`; если `ADMIN_PASSWORD` пуст, создаётся случайный одноразовый пароль (пароля по умолчанию нет). Пароль не короче 10 символов.

Откройте `https://ваш-домен`, войдите и сразу смените пароль.

При первом запуске программа создаёт пустую базу со стандартным литовским планом счетов и одного администратора (скрипт `web/scripts/bootstrap.cjs`). Существующая база никогда не изменяется стартовым скриптом, а миграции применяются приложением при первом обращении к данным.

## Перенос существующих данных

Остановите приложение, положите файл базы в `deploy/data/dev.db` (рядом не должно быть старых `dev.db-wal` и `dev.db-shm`), выполните `chown 1000:1000`, запустите. Ключ `SMTP_ENCRYPTION_KEY` должен быть тем же, что на старом сервере, иначе сохранённые пароли SMTP не расшифруются. Если базы нет, создайте компанию в разделе «Управление компаниями»; данные другой системы можно загрузить импортом пакета компании.

## Что нужно сохранять

- **База:** `deploy/data/dev.db`. Резервную копию работающей базы делайте через SQLite backup, а не копированием файла: `docker exec kontas-app node -e "const D=require('better-sqlite3');new D('/app/prisma/dev.db',{readonly:true}).backup('/tmp/b.db').then(()=>console.log('ok'))" && docker cp kontas-app:/tmp/b.db ./backup-$(date +%F).db`. Администратор может также скачать копию из программы (`/api/admin/backup`).
- **Ключ `SMTP_ENCRYPTION_KEY`:** храните отдельно от бэкапов базы; без него сохранённые пароли SMTP не читаются, и их придётся ввести заново.
- Копии храните вне этого сервера.

## Обновление

```bash
git pull
docker compose -f docker-compose.server.yml --env-file .env up -d --build
```

Перед обновлением сделайте копию базы. Миграции базы применяются автоматически и только добавляют новое.

## Сброс пароля

```bash
docker exec -it kontas-app node scripts/set-password.cjs admin@example.com          # новый случайный пароль
docker exec -it kontas-app node scripts/set-password.cjs admin@example.com 'мой-длинный-пароль'
docker exec -it kontas-app node scripts/set-password.cjs admin@example.com --enable  # заодно включает отключённую учётную запись
```

Пароль не короче 10 символов; все сессии пользователя завершаются, а блокировка попыток входа снимается. Если учётная запись отключена, без `--enable` пароль изменится, но войти всё равно не получится (скрипт предупредит об этом); включить пользователя можно и в разделе «Пользователи».

## Проверка работоспособности

`docker ps` показывает статус `healthy` у `kontas-app` (Dockerfile проверяет страницу `/login` каждые 30 с). Журналы: `docker logs -f kontas-app`.

## Исходящая почта

Для отправки счетов и напоминаний серверу нужен доступ к SMTP-серверу (порты 465 или 587). Некоторые хостинги закрывают их: если письма не уходят, используйте SMTP-сервис своего почтового провайдера или попросите открыть порт. Настройки SMTP вводятся в карточке каждой компании.

## Безопасность

Наружу открыты только 80 и 443 (Caddy); приложение доступно лишь внутри сети Docker. Включите автоматические обновления ОС и файрвол. Не публикуйте файл `.env` и каталог `data`. Подробнее: [../web/SECURITY.ru.md](../web/SECURITY.ru.md).
